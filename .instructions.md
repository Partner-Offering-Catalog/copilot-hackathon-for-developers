# Markdown authoring instructions

Write concise, audience-appropriate Markdown with descriptive headings, short
paragraphs, and ordered steps for procedures. Use relative links for
repository files, fenced code blocks with a language when known, and
alt text for meaningful images.

Place application and operational documentation in `docs/`. Keep the root
`README.md` limited to onboarding and repository-level guidance. Do not create
planning or scratch Markdown files unless the user explicitly requests them.

Do not edit Markdown files under `.github/`; those are maintained by
repository owners. Do not include secrets, personal data, or internal URLs.
